## qbittorrent-skip-hash-check.bat 报「登录失败」修复并运行
- **根因**：非账号密码问题，而是 WebAPI 版本兼容。登录判定写成 `r.status_code != 200 or 'Ok.' not in r.text`，
  但当前 qBittorrent 登录成功返回 **HTTP 204 No Content**（响应体为空，旧版才是 200 + "Ok."），故误判失败。
  curl 实测：带/不带 Referer 均返回 204 且正常下发 `QBT_SID_9091` Cookie → 凭据正确。
- **修复**（两个脚本都改，同一 bug）：
  - `login()` 判定改为 `200 <= status < 300`，并额外校验 session 中是否出现 `QBT_SID*` Cookie 做二次确认。
  - 保留/补上 `Referer` 头（新版 qb 的 CSRF 校验要求 Referer 与 Host 一致）。
  - `skip-hash-check.py` 补控制台 UTF-8 reconfigure（打印 ✅/❌，GBK 控制台会 UnicodeEncodeError）。
- **bat 改进**：末尾加 `errorlevel` 判断 + `pause`，避免双击运行后窗口秒关闭看不到报错（本身也易被误判为"异常"）。两个 bat 均已加。
- **环境变化**：系统 Python312 已被移除，现为 `C:\Users\Schal\AppData\Local\Programs\Python\Python313\python.exe`（双击 bat 走它）；
  已给它装 requests/pandas/openpyxl，托管 python(3.13.12/3.14.3) 也已装，两种终端都能跑。
- **运行结果**：登录恢复正常，`--filter all` 可拉到 41015 个种子；当前状态分布 stalledUP 37221 / stoppedUP 3780 / uploading 12 / stoppedDL 2，
  **无任何 checkingUP/checkingDL**，故 `--skip-check` 跳过 0 个属真实情况，非脚本漏判。

## 追加：两个脚本支持 API token 鉴权（qBittorrent 5.2+）
- 新增共享模块 `qb_auth.py`（QBClient + add_auth_args + build_client_from_args），两个脚本改为复用它，
  函数签名从 `(session, base_url)` 统一改为 `client`。
- 实测依据（curl）：`Authorization: Bearer` → 200 / v5.3.0；`X-API-Key` → 403；token 调 auth/login → 403。
  故统一用 Bearer，且不能用 login 验 token，改探测 `/api/v2/app/version`。
- 优先级 token > 用户名密码（与服务端一致）；token 格式校验 `qbt_`+28 位=32 字符。
- 密码模式结束主动 logout 释放会话；token 模式免处理。
- 请求统一加 timeout (10, 60)，4 万种子 info 响应数十 MB 不会超时。
- bat 改为 `if defined TOKEN` 分支，优先用 token；两个 bat 均已填用户 token。
- 验证：token 模式 skip-check 跑通；tagger dry-run 扫描 40982 个种子 90s 完成（错误 818 / 警告 249 / 涉及 1064）。
  无效 token、错误格式 token、密码回退三种路径均有正确报错。
- 性能答复：单次运行收益可忽略（省 1 次往返 + PBKDF2 5–50ms），真正受益的是高频轮询与免封 IP/免会话堆积。
